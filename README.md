# Industry Niche Atlas

An atlas for exploring industries, occupations, tasks and narrow work niches,
alongside skill roadmaps and a world map of administrative geography. Every
figure comes from a published source — O\*NET, BLS, GeoNames, geoBoundaries,
NAICS/ISIC/ISCO — and each layer carries its provenance into the interface
rather than into a footnote. The current release covers 1,016 occupations,
18,796 task statements, 2,125 NAICS industries and 93 roadmaps.

## Shape of the thing

One Vite-built React SPA and one Cloudflare Worker, and that is the whole
deployment. The Worker is not a separate backend tier: it serves the static
assets, the JSON data releases, the packed vector tiles and the `/api/*`
endpoints from a single origin.

```
client/           React 19 SPA — Vite 7, Tailwind 4, shadcn/ui, wouter
  public/data/    the committed data releases the SPA fetches
worker.ts         the entire server: assets, tiles, /api/*
migrations/       D1 schema, applied by CI after a green build
scripts/          the data pipeline (Python) and derived-payload builders (Node)
shared/           types used by both the SPA and the Worker
tests/            Vitest — tests/client and tests/worker
```

### Routes

| Path                                | Page                                                          |
| ----------------------------------- | ------------------------------------------------------------- |
| `/`                                 | the atlas itself — industries, occupations, and the world map |
| `/roadmaps`                         | roadmap catalogue                                             |
| `/roadmaps/:slug`                   | one roadmap, with progress and notes                          |
| `/roadmaps/plan`                    | goal-driven study planner                                     |
| `/ai/roadmap`, `/ai/roadmap/result` | generate a roadmap for an arbitrary topic                     |

`/roadmaps/plan` is declared before `/roadmaps/:slug` on purpose; the slug
pattern would otherwise swallow it.

### API

Four endpoints, all same-origin, all anonymous.

| Endpoint          | Methods       | Notes                                                |
| ----------------- | ------------- | ---------------------------------------------------- |
| `/api/state`      | `GET`, `POST` | favourites, per-roadmap progress, notes, saved plans |
| `/api/ai/roadmap` | `POST`        | Workers AI, quota-limited                            |
| `/api/ai/plan`    | `POST`        | Workers AI, quota-limited                            |
| `/api/ai/chat`    | `POST`        | Workers AI, quota-limited                            |

Identity is a server-minted opaque token in an `HttpOnly` cookie. There is no
login, and there is deliberately no way to name a profile from the client — a
client-supplied profile id would let any caller read or overwrite anyone's
state, which is exactly what the earlier `?profile=` parameter did.

## Data

Two kinds of file live under `client/public/data`, and the distinction matters
when reading a diff:

- **Committed source of truth.** `manifest.json`, `occupations.json`,
  `taxonomies.json`, `roadmap-content.json`, `roadmap-graphs.json`, the
  `world-mvt/<release>/` tile shards. These are the provenance record.
- **Derived, and gitignored.** `occupations-index.json`,
  `occupations-detail.json`, `roadmaps/<slug>.json`,
  `world-mvt/manifest.json`. Pure functions of the above, regenerated by
  `pnpm data:derive`, which `dev` and `build` both run. Committing them would
  duplicate about 32 MB of already-committed bytes.

The derivations exist because the monoliths are too big to send to a browser: a
6.6 MB occupations file became a 133 KB-gzipped index plus a detail file fetched
behind it, and an 8.27 MB tile manifest became 12.9 KB once the exhaustive tile
listing nothing read was dropped. See `PERFORMANCE_BUDGET.md`.

### Rebuilding the release from source

The Python pipeline downloads and rebuilds the official release. It is not part
of `pnpm build` — it runs monthly in CI, or by hand:

```bash
python -m pip install openpyxl && pnpm data:refresh
```

World tiles are built separately and offline, because the inputs are tens of
gigabytes; `scripts/KAGGLE_WORLD_BUILD.md` documents that path.

## Working on it

Node 22 and pnpm 10 (via corepack). `pnpm dev` derives the client payloads and
then starts Vite; the SPA alone is enough for everything except `/api/*`.

```bash
pnpm install
pnpm dev
```

To exercise the Worker — tiles, state, AI — run it under wrangler instead, which
uses a local miniflare D1 rather than the real one:

```bash
pnpm build && npx wrangler dev
```

### The gate

CI runs exactly this, and refuses to deploy if any step fails:

```bash
pnpm check && pnpm lint && pnpm test && pnpm build
```

`pnpm check` is three TypeScript projects — the SPA, the Worker, and the build
scripts — because a single one cannot cover three different sets of globals.

## Deploying

Push to `main`. `.github/workflows/deploy-cloudflare.yml` runs the gate, applies
D1 migrations, and then deploys the Worker; it needs `CLOUDFLARE_API_TOKEN` and
`CLOUDFLARE_ACCOUNT_ID` in Actions secrets and skips itself when they are absent.

Migrations are applied _after_ the build, not before. Applying them first meant a
failing build left production D1 on a schema no deployed Worker used.

The monthly data refresh opens a pull request rather than pushing to `main`: a
commit authored by `GITHUB_TOKEN` cannot trigger a workflow, so pushing directly
would land new data that never deployed.

## Known gaps

- `preview_database_id` in `wrangler.jsonc` still equals `database_id`, so
  `wrangler dev --remote` and any preview deployment write to **production** D1.
  Fixing it needs account credentials: `npx wrangler d1 create atlas-roadmaps-preview`,
  then paste the returned id. Plain `wrangler dev` is unaffected.
- Roughly 807 MB of tile shards are committed to git. R2 is the right home for
  them; moving them means rewriting history, which is its own project.
- No raster social card exists, so `og:image` is deliberately absent rather than
  pointing at a 404.
